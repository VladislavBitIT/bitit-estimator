ИНСТРУКЦИЯ К БОТУ BIT.IT

Что запускаем

telegram_bot.py — весь Python-код этой версии: 60 строк, одна функция reply.
Он не использует bot.py, estimator.py и другие модули прежнего прототипа.
Нужны две готовые библиотеки: pyTelegramBotAPI (связь с Telegram) и requests (запрос к OpenRouter).
Инструкция подготовлена ассистентом для этого проекта; это не материал преподавателя.

Как проходит один запрос

1. Ты присылаешь обезличенное ТЗ одним текстовым сообщением в личный чат бота.
2. Python проверяет, есть ли твой Telegram ID в разрешённом списке.
3. К новому ТЗ добавляется текстовая база прошлых проектов.
4. Всё отправляется нейросети через OpenRouter.
5. Ответ дописывается в локальную историю и отправляется в Telegram.

Какие файлы нужны

telegram_bot.py — программа, которую разбираем перед защитой.
prompt.txt — правила ответа нейросети обычными русскими словами; их можно менять.
private/projects.txt — подготовленная база из шести реальных обезличенных ТЗ с ценами.
private/bot_settings.json — токен бота, ключ OpenRouter, название модели и разрешённые Telegram ID.
private/answers.txt — новые ТЗ и ответы; файл появится после первого успешного запроса.
bot_settings.example.json — пустой шаблон настроек для репозитория.

Папка private исключена из git. Даже обезличенные реальные цены туда не публикуем.
При передаче проекта преподавателю рабочие данные согласуем отдельно.
ТЗ и база при оценке передаются OpenRouter и выбранному провайдеру модели.
В запросе сохранены ограничения data_collection=deny и zdr=true; если подходящего провайдера нет,
запрос завершится ошибкой. Эти настройки не отменяют саму передачу данных внешнему сервису.

Как запустить

В терминале перейди в папку проекта:

cd '/Users/vladislavplesivcev/Documents/ChatGPT/Python ИИМУП/Проект — Оценки и предложения BIT IT'

Библиотеки в текущем окружении уже установлены. На другом компьютере:

python3 -m pip install -r requirements.txt

1. В private/bot_settings.json впиши telegram_bot_token из BotFather. Ключи остаются на ноутбуке.
2. Запусти:

python3 telegram_bot.py

3. Отправь боту любое текстовое сообщение. При закрытом доступе он вернёт твой числовой Telegram ID.
4. Останови программу сочетанием Ctrl+C.
5. В настройках запиши свой ID в allowed_user_ids: например, [123456789]. Это выдуманный пример ID.
   Для коллег добавляй ID через запятую. Числа пишем без кавычек. Пустой список закрывает доступ всем.
6. Заполни openrouter_api_key. Поле openrouter_model позволяет менять модель без изменения кода.
7. Снова запусти python3 telegram_bot.py и пришли обезличенное ТЗ текстом.

Если токен пока пустой, программа сообщит об отсутствии токена и завершится без сетевых запросов.
Для получения ID достаточно токена Telegram. Ключ OpenRouter нужен при запросе оценки.
После изменения настроек, базы или инструкции перезапускай программу.
Бот работает, пока запущена программа. После перезапуска старые ожидающие сообщения пропускаются.

Как читать код

Сначала читаем верхний блок: импорт библиотек и открытие трёх файлов.
import подключает библиотеку. json.load читает настройки как словарь — набор пар «название: значение».
settings["openrouter_model"] достаёт значение по названию. file.read() читает текст файла.
with open(...) открывает файл и закрывает его после блока с отступом. encoding="utf-8" нужно для русского текста.

Весь путь сообщения находится в одной функции reply(message).
Библиотека вызывает её, когда приходит текстовое сообщение.
В начале if проверяет тип чата и доступ пользователя. return прекращает обработку текущего сообщения.
message.text — текст сообщения, message.chat.id — куда отправить ответ, message.from_user.id — кто написал.
Если пользователя нет в разрешённом списке, он получает свой ID для настройки доступа, а запрос к модели не выполняется.
Команды и пустые сообщения получают подсказку; остальные сообщения отправляются на оценку.

Внутри этой же функции составляется запрос к OpenRouter.
requests.post отправляет HTTP-запрос — сообщение внешнему сервису через интернет.
headers содержит ключ доступа, json — данные запроса. Это способ общения с OpenRouter из его документации.
system — инструкция нейросети, user — прошлые проекты и новое ТЗ.
max_tokens ограничивает длину генерируемого ответа. timeout ограничивает ожидание сервиса.
response.raise_for_status() сообщает об ошибке сервиса, например о неверном ключе или отсутствии баланса.
response.json() читает присланные сервисом данные. choices[0] берёт первый вариант ответа.
finish_reason="stop" означает, что модель завершила ответ; обрезанный ответ не сохраняем как оценку.
answer — переменная с текстом ответа, извлечённым из присланных данных.
open(..., "a") дописывает ответ в конец истории, сохраняя прежние записи.
for отправляет длинный ответ частями. answer[start:start + 2000] берёт очередной фрагмент текста.
try/except перехватывает ошибку обработки сообщения и отправляет понятное уведомление.
Общий except Exception оставлен для короткой учебной версии; он не различает причины ошибок.
Внизу bot.register_message_handler(reply, ...) сообщает библиотеке, какую функцию вызывать при сообщении.
reply здесь передаётся без скобок: функция будет вызвана библиотекой позже, когда придёт текст.
Последняя строка bot.infinity_polling(...) запускает ожидание новых сообщений.

Что можно изменить на защите

Изменить приветствие в bot.send_message.
Изменить размер частей ответа с 2000 на 1500.
Изменить требования к ответу в prompt.txt.
Добавить ещё один реальный завершённый проект в private/projects.txt и перезапустить бота.

Границы этой версии

Вход — только текст одним сообщением. Файлы, изображения и склеивание нескольких сообщений не реализованы.
База читается целиком при запуске. CSV-импорта, меню редактирования и команды просмотра истории нет.
История остаётся в private/answers.txt; она не добавляется автоматически в базу реальных оценок.
Python не рассчитывает стоимость по своей формуле и не проверяет правильность названных моделью цен.
Числа и выбор исполнителя предлагает нейросеть. На шести примерах точность прогноза не подтверждена.
Упрощение не гарантирует выполнение всех критериев исходной заявки: в частности,
нет собственной логики ценообразования и разделения Python-кода на модули.
Называем это прототипом помощника по предварительной оценке и не выдаём его за проверенный расчётчик.
Автоматических повторов HTTP-запроса нет. Ручная повторная отправка ТЗ создаст новый запрос и запись истории.
Ошибка ожидания не гарантирует, что внешний сервис не успел обработать запрос и списать оплату.
Проверка без ключей не доказывает, что настоящее соединение с сервисами работает: его проверим после настройки.

Проверка ассистента

Фактически прошли 15 проверок с подставными данными и ответами, без сетевых запросов:
передача ТЗ и базы, сохранение после перезапуска, доступ, длинный ответ, ошибки и отсутствие ключей.
Скрипт проверок сохранён отдельно, в private/проверка_бота_ассистент.py. Он не нужен для запуска бота.
Повторный запуск из папки проекта: python3 private/проверка_бота_ассистент.py
