# Bit.IT — Telegram-помощник по оценке разработки

Учебный проект «Автоматизируй свою рутину», дисциплина «Программирование на Python», ИИМУП.
Владелец агентства получает новое ТЗ и долго ждёт оценку исполнителя.
Бот передаёт ТЗ и прошлые проекты нейросети и показывает ориентировочную стоимость,
диапазон и обоснование выбора разработчика.

Рабочая версия — `telegram_bot.py`, один файл и две функции.
Другие Python-файлы в корне сохранены от предыдущих учебных версий и при этом запуске не используются.

## Файлы текущей версии

| Файл | Назначение |
| --- | --- |
| `telegram_bot.py` | Работающая программа |
| `prompt.txt` | Инструкция нейросети: какие оценки и объяснения вернуть |
| `bot_settings.example.json` | Шаблон настроек без ключей |
| `projects.example.txt` | Четыре вымышленных проекта для проверки запуска, не реальные цены Bit.IT |
| `requirements.txt` | Библиотеки для установки |
| `private/bot_settings.json` | Локальные ключи, модель и разрешённые Telegram ID |
| `private/projects.txt` | Локальная база проектов: в работе автора здесь шесть реальных обезличенных ТЗ |
| `private/answers.txt` | Новые ТЗ и полученные ответы; создаётся при первой успешной оценке |

`README.md` — инструкция человеку по запуску. `prompt.txt` — инструкция модели по ответу.
Python читает `prompt.txt` и передаёт его модели, а README не читает.

## Установка и запуск без изменения кода

Нужны Python 3.9 или новее, интернет, доступ к закрытому репозиторию, токен своего Telegram-бота
и API-ключ OpenRouter. Ключи вводятся в локальные настройки, а не в Python-код.
В `requirements.txt` закреплены версии библиотек, на которых выполнены проверки.

Для macOS и Linux:

```bash
git clone --branch codex/bitit-telegram-bot https://github.com/VladislavBitIT/bitit-estimator.git
cd bitit-estimator
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
mkdir -p private
cp -n bot_settings.example.json private/bot_settings.json
cp -n projects.example.txt private/projects.txt
```

На Windows окружение создаётся командой `python -m venv .venv`, активируется через
`.venv\Scripts\activate`. Папку `private` и копии двух файлов можно создать в проводнике.
`cp -n` в примере сохраняет уже существующие файлы: рабочая база и ключи не заменяются примерами.

1. В `private/bot_settings.json` заполните `telegram_bot_token` из BotFather.
2. Запустите программу из папки проекта:

   ```bash
   python telegram_bot.py
   ```

3. Отправьте своему боту любое текстовое сообщение. При пустом списке доступа он покажет ваш числовой Telegram ID.
4. Остановите программу: Ctrl+C. Добавьте ID в `allowed_user_ids` как число без кавычек.
5. Заполните `openrouter_api_key`. В шаблоне `openrouter_model` указан `openrouter/free`.
6. Снова запустите программу и отправьте обезличенное ТЗ одним текстовым сообщением.

Для другого разработчика или коллеги добавляйте его ID в тот же список через запятую.
После изменения настроек, базы или `prompt.txt` перезапустите программу.
Должен работать один экземпляр бота. Пока работает программа и есть интернет, бот принимает сообщения.
После запуска прежние ожидающие сообщения пропускаются — для проверки отправьте новое.

Для защиты на реальных данных автор использует локальный `private/projects.txt`,
а файл `projects.example.txt` нужен для воспроизведения запуска без публикации рабочих цен.

## Две функции

- `get_estimate(task)` получает текст нового ТЗ, отправляет запрос модели и **возвращает текст ответа**.
- `reply(message)` получает сообщение Telegram, проверяет доступ, вызывает первую функцию,
  сохраняет результат и отправляет его пользователю.

Настройки — словарь, разрешённые ID и сообщения для API — списки.
База и инструкция модели читаются из файлов. История открывается с режимом `a`: новые записи
добавляются в конец и сохраняются после перезапуска. Если запись истории не удалась,
бот сообщает об этом и всё равно показывает полученный ответ.

Числовые параметры выделены в именованные константы:

- `REQUEST_TIMEOUT` — время ожидания OpenRouter в секундах;
- `MAX_OUTPUT_TOKENS` — предел длины ответа модели в единицах текста модели;
- `MESSAGE_CHUNK_SIZE` — число символов в одной отправляемой части ответа.

## Ошибки и ручная проверка

| Проверка | Ожидаемое поведение |
| --- | --- |
| Нет файла настроек, базы или `prompt.txt` | Программа завершается с названием недоступного файла |
| Ошибка JSON или кодировки файла | Понятное сообщение о формате; бот не запускается |
| Пустая база или инструкция модели | Сообщение о пустом файле; бот не запускается |
| Токен Telegram пустой или имеет неверный формат | Сообщение о токене; бот не запускается |
| В JSON вместо словаря или списка ID указан другой тип | Сообщение о настройках; бот не запускается |
| Пишет пользователь вне списка или сообщение пришло из группы | Запрос к модели не выполняется |
| Пришла команда или пустое ТЗ | Подсказка; запрос к модели не выполняется |
| Сеть недоступна или истекло время ожидания | Сообщение о недоступности OpenRouter |
| Сервис вернул ошибку | Бот показывает HTTP-код: 401 — ключ, 402 — баланс, 429 — лимит запросов |
| Модель вернула неверный формат, пустой или незавершённый ответ | Ошибка показывается, запись оценки не создаётся |
| Историю нельзя записать | Бот предупреждает и показывает ответ без сохранения |
| Ответ слишком длинный | Он отправляется несколькими сообщениями |
| Программа перезапущена | Предыдущая история остаётся в `private/answers.txt` |

Для этих сбоев используются конкретные `except`: `OSError`, ошибки JSON и кодировки,
`requests.HTTPError`, `requests.RequestException`, `ValueError` и ошибки формата ответа.
Общего `except Exception` в рабочем файле нет. Ошибки не скрываются.
Локально прошли 27 автоматических проверок с подставными ответами. Дополнительно проверен запуск
в чистой папке с поставляемыми примерами и подставными ключами, без изменения Python-кода.
Автоматических повторов запроса к модели нет. Повторная отправка ТЗ пользователем — новый запрос.

## Реальные данные и найденные проблемы

Автор передал шесть завершённых проектов двух разработчиков; суммы названы разработчиками за ТЗ целиком.
Выполнение работ подтверждено автором, совпадение оценки с окончательной выплатой не подтверждено.

При подготовке данных:

1. Цены с разделителями тысяч и обозначением валюты перенесены в единый вид; исходные материалы сохранены локально.
2. Тарифы услуг и проценты внутри ТЗ отделены от цены разработки.
3. Отсутствующие даты, сроки и итоговые выплаты не придуманы и не подменены датами из текста ТЗ.
4. Создание новой системы и доработка существующей описаны раздельно: одинаковая технология не означает одинаковый объём.
5. Имена и названия контрагентов заменены. Подтверждённых дополнительных навыков разработчиков нет.
6. Малая база и отсутствие новых контрольных оценок не позволяют подтвердить точность прогнозов.

Нейросеть предлагает предварительный ориентир. Собственной формулы цены и наценки клиенту в этой версии нет.
В исходном комментарии к заявке преподаватель выделял собственную логику цены;
особенность текущего варианта с LLM нужно честно объяснить на защите.

## Присланные критерии преподавателя

Источник — сообщение преподавателя из общего чата, переданное автором проекта.
Сумма пунктов — 10 баллов по рубрике; максимум за проект — 2 балла к итоговой оценке.

| Критерий | Максимум | Что показывать |
| --- | --- | --- |
| Работающее решение реальной задачи | 2 | Запуск по README, реальная локальная база и получение оценки |
| Материал курса | 2 | Аргумент и `return` в `get_estimate`, словарь, списки, чтение и запись файлов |
| Надёжность | 1,5 | Проверки из таблицы ошибок и конкретные блоки `except` |
| Качество кода | 1,5 | Две функции с понятными именами и именованные параметры |
| Понимание на защите | 3 | Объяснение пути одного ТЗ и самостоятельное небольшое изменение |

Это соответствия для подготовки к защите, а не обещание баллов.
Первый пункт требует живой демонстрации: подключение Telegram проверено,
но последний пробный запрос бесплатной модели вернул HTTP 429. Успешное получение оценки
настоящей моделью ещё нужно подтвердить; локальные проверки с подставными ответами его не заменяют.

## Конфиденциальность

`private/`, `data/`, исходные клиентские документы, ключи и реальные цены исключены из git.
В публичных примерах используются только вымышленные данные.
Во время оценки ТЗ и база передаются OpenRouter и провайдеру модели.
В коде сохранены `data_collection: deny` и `zdr: true`; при отсутствии совместимого провайдера
запрос завершится ошибкой. Эти параметры не отменяют саму передачу данных внешнему сервису.

Технические источники: [OpenRouter API](https://openrouter.ai/docs/api/api-reference/chat/create-a-chat-completion),
[ограничения провайдеров](https://openrouter.ai/docs/guides/routing/provider-selection),
[Telegram-библиотека](https://pytba.readthedocs.io/en/latest/sync_version/index.html).
