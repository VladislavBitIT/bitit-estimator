# Bit.IT — Telegram-помощник по оценке разработки

**Запуск Telegram-бота:** `python3 telegram_bot.py`.
Весь её Python-код находится в одном файле: 60 строк и одна функция, без декораторов.
Порядок запуска, объяснение конструкций и ограничения — в [ИНСТРУКЦИЯ.txt](ИНСТРУКЦИЯ.txt).
Реальные шесть ТЗ с оценками собраны в локальном `private/projects.txt`;
настройки — в `private/bot_settings.json`, ответы дописываются в `private/answers.txt`.
Эта версия принимает только текст и получает свободный ответ модели; собственной формулы цены в ней нет.
При закрытом доступе бот показывает пользователю его ID; отдельной команды `/id` здесь нет.
Ключи настроены, подключение к Telegram проверено. Последний учебный запрос к бесплатной модели OpenRouter вернул HTTP 429.
Описание ниже относится к сохранённому прежнему прототипу `bot.py`.

Учебный проект «Автоматизируй свою рутину», дисциплина «Программирование на Python», ИИМУП.

## Задача и текущие решения

Владелец агентства долго ждёт ответов разработчиков и ищет прошлые оценки в переписках и таблицах.
Бот должен принимать новое ТЗ, сопоставлять его с историей работ и показывать ориентир цены,
диапазон, использованные примеры и обоснование выбора исполнителя.

По последним пояснениям автора:

- Все переданные работы выполнены; это ранние проекты для проверки двух разработчиков.
- Каждая сумма названа самим разработчиком за соответствующее ТЗ целиком.
- Совпадение оценки и фактической выплаченной суммы не подтверждено.
- Разработчики примерно одного уровня. Дополнительные подтверждённые навыки пока не указаны.
- Сроки для первой версии не приоритетны. Отсутствующие сроки и даты остаются пустыми.
- Вход — текст сообщения или файл с ТЗ. Пользователи — владелец и его коллеги.
- Дополнительных правил цены клиенту нет; расчёт наценки в текущий прототип не входит.
- Отдельных примеров для проверки точности прогноза пока нет.

## Что написано

Первый прототип на Python с небольшими функциями и двумя внешними библиотеками:
`pyTelegramBotAPI` для Telegram и `requests` для обращения к OpenRouter.
Асинхронные функции, собственные классы, обучение модели и агентские фреймворки не используются.

Сценарий:

1. Пользователь из разрешённого списка присылает ТЗ в личный чат бота.
2. Из сообщения, TXT или DOCX извлекается текст. Файлы ограничены 2 МБ, текст — настройкой `max_task_chars`.
3. Новое ТЗ, обезличенная история и подтверждённые профили отправляются одним запросом модели.
4. Python проверяет ответ: разработчики известны, цены положительны, диапазон согласован,
   ссылки на примеры существуют и относятся к соответствующему разработчику.
5. Проверенный ответ сохраняется и показывается пользователю. При недостатке аналогов
   допускается ответ без цены. Выбор одного разработчика не обязателен.
6. Команда `/history` показывает последние три расчёта текущего пользователя.

Каждый расчёт хранится отдельно в `data/calculations/`, вместе с исходным ТЗ, названием модели,
копией использованной истории, профилей и инструкций. Изменение исходной базы не меняет старый расчёт.
Повтор обработки того же Telegram-сообщения использует сохранённый результат.
Новые предположения модели автоматически не добавляются в базу реальных оценок.

**Статус:** код проверен локально с подставными ответами. Бот ещё не подключён к Telegram,
запросы настоящей модели не выполнялись: токен и ключ не настроены. Начальная модель выбрана по документации.

## Требования курса и важное ограничение

Источники: [задание преподавателя](https://docs.google.com/document/d/1w9Jqy6vxUEwnt321h48pbeH0QQF9sxlmqBvuFP2akFI/edit?tab=t.0)
и [одобренная заявка, строка 14](https://docs.google.com/spreadsheets/d/1LdwI4Viism1Y5hDiHUArToFcoCX5NvV0vVzNgSvfIA8/edit#gid=1952612017&range=G14:H14).

Требуются реальные данные, собственная объяснимая логика, обработка найденных ошибок,
сохранение состояния, функции и модули, последовательные коммиты и понимание кода на защите.
Личные данные и закрытые финансовые сведения в репозиторий не помещаются.

Исходная заявка одобрена для базовой группы: «От меня ОК». Преподаватель отдельно
подчеркнул собственные содержательные правила цены и тестирование на обезличенных данных.
Текущий замысел уточнён в сторону LLM-помощника. Проверка формата ответа и ссылок полезна,
но сама по себе не является авторским правилом ценообразования. Соответствие этого
упрощённого варианта критерию собственной логики стоит отдельно обсудить с преподавателем.
Выдумывать наценки или коэффициенты, которых нет в работе агентства, не будем.

В материалах курса этого нет: конкретная архитектура AI-помощника и правила прогноза Bit.IT.
Выбранная структура — решение для этого проекта, а не требование преподавателя.

## Проверка без ключей и расходов

Из папки проекта:

```bash
python3 bot.py --check
python3 -m unittest discover -s tests -v
```

Фактически выполнено на Python 3.13.2: **27 тестов прошли**. Локальная проверка прочитала
шесть реальных ТЗ и два профиля. Новый обработчик прочитал все три исходных Word-файла.
Сетевые вызовы в тестах подставные; проверена и обработка сообщений через библиотеку Telegram.
Это проверка кода и работы с данными, а не точности прогнозов настоящей модели.

Если зависимости ещё не установлены, создайте отдельное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

## Настройки и первый запуск

Файл `private/settings.json` уже подготовлен с пустыми ключами. Публичный
`settings.example.json` — только шаблон: настоящие ключи туда не записываем.

В локальном файле настроек нужно заполнить:

- `telegram_bot_token` — токен собственного бота из BotFather.
- `openrouter_api_key` — ключ OpenRouter.
- `openrouter_model` — для первого запуска указан `qwen/qwen3-30b-a3b-instruct-2507`.
  По [странице модели](https://openrouter.ai/qwen/qwen3-30b-a3b-instruct-2507) и публичному
  списку endpoints проверены доступность модели, тарифы и поддержка JSON-ответа.
  Качество оценок и рабочий вызов с настройками приватности ещё не проверены.
  Модель можно заменить в этом поле без изменения Python-кода.
- `allowed_user_ids` — числовые Telegram ID владельца и коллег.

Сначала можно заполнить только токен Telegram, запустить `python3 bot.py`
и отправить боту `/id`. Команда показывает собственный ID и не раскрывает рабочие данные.
После добавления разрешённых ID и настроек OpenRouter перезапустите процесс.
Пустой список ID закрывает доступ к оценкам всем пользователям.

Команды: `/start`, `/help`, `/id`, `/history`. Для оценки достаточно прислать ТЗ.
Файлы PDF, изображения и сканы в текущем прототипе не поддерживаются.
Присылаемые материалы должны быть обезличены. DOCX читается как текст: встроенные изображения
и содержимое колонтитулов не анализируются, разметка таблиц преобразуется в последовательность текста.
Бот работает, пока запущена программа; постоянное размещение на сервере пока не настроено.

Перед реальными вызовами выбираем недорогую модель и задаём лимит расходов для ключа OpenRouter.
Программа не меняет баланс и лимиты аккаунта. Размер ответа ограничен настройкой `max_output_tokens`.
После ошибки запроса программа не выполняет автоматический платный повтор.
Тайм-аут не доказывает, что провайдер не обработал запрос или не списал стоимость.

## Как устроен код

| Файл | Назначение |
| --- | --- |
| `bot.py` | Настройки, разрешённые пользователи, команды, соединение шагов обработки |
| `task_files.py` | Извлечение текста из TXT/DOCX, проверки размера и формата |
| `estimator.py` | Чтение истории, подготовка данных для модели, проверка и оформление ответа |
| `openrouter_client.py` | Один HTTP-запрос к OpenRouter и обработка ошибок сервиса |
| `calculation_history.py` | Чтение и сохранение отдельных расчётов |
| `model_instructions.txt` | Явные инструкции модели: аналоги, ограничения и формат ответа |
| `settings.example.json` | Шаблон настроек без ключей и рабочих цен |
| `tests/` | Проверки на синтетических данных ассистента |

`def` объявляет функцию, `if` выбирает действие, `for` перебирает записи,
`dict` хранит поля записи, `list` — набор записей. `try/except` обрабатывает ожидаемые ошибки.
JSON — текстовый формат для данных. HTTP-запрос передаёт эти данные сервису и получает ответ.
Конструкции `@bot.message_handler(...)` регистрируют функции, которые библиотека вызывает
при подходящем сообщении. Это новые для разбора конструкции; будем проходить их по одному сценарию.

`main.py`, `storage.py` и их тесты сохранены как первая учебная версия с текстовым меню проектов.
Она запускается отдельно через `python3 main.py` и не управляет текущей базой оценок бота.

## Рабочие данные и конфиденциальность

Все исходники, цены и локальные параметры находятся в `private/`; расчёты — в `data/`.
Оба каталога исключены из git. Шаблон настроек — единственное исключение для JSON в корне.

- `private/01_Исходники/` — три неизменённых DOCX, снимок Google Docs, два ТЗ из сообщения,
  исходные оценки и отдельные уточнения автора. Контрольные суммы исходных файлов проверены.
- `private/02_Извлечённые_тексты/` — тексты до обезличивания.
- `private/03_Обезличенные_данные/` — обезличенные ТЗ, последовательные версии оценок,
  профили и CSV. Активная версия — `оценки_v3.json`, заполнение навыков — `профили_v1.json`.
- `private/Соответствия_имён.json` — локальное соответствие кодов и исходных имён.
- `data/calculations/` — созданные ботом расчёты и копии их исходных данных.

Найденные названия контрагентов, имена, сайт и внутренние идентификаторы заменены в производных
текстах. Bit.IT и названия программ сохранены. Даже обезличенные рабочие суммы не коммитим.
Перед коммитом проверяем список добавленных файлов. `.gitignore` не шифрует данные на диске.

При рабочем запросе ТЗ и история уходят через OpenRouter провайдеру выбранной модели.
В коде включены `provider.data_collection: deny` и `provider.zdr: true`; если подходящего
провайдера нет, запрос завершится ошибкой. Это ограничение маршрутизации и хранения у провайдера,
а не запрет самой передачи данных или гарантия отсутствия любых метаданных у OpenRouter.

## Найденные ошибки и крайние случаи

В реальных материалах:

1. Цены представлены строками с разделителем тысяч и обозначением валюты. Они отдельно
   перенесены в целые рубли и сверены; исходные строки сохранены.
2. Внутри ТЗ встречаются тарифы услуг и проценты. Они не используются как стоимость разработки.
3. Отсутствуют даты оценок, сроки и фактические суммы. Пропуски оставлены пустыми;
   даты документов, периоды аренды и длительность клиентского проекта их не заменяют.
4. Одни ТЗ описывают создание системы, другие — доработку существующей. Это учитывается
   в описании задачи и инструкциях сопоставления; общая средняя цена разработчика не вычисляется.
5. Есть зависимость от существующих файлов, альтернативы дополнительного блока,
   повреждённая фраза и неуточнённая граница тарифов. Замечания сохранены у записей;
   содержание отсутствующих материалов не придумано.
6. Автор подтвердил выполнение всех работ, но это не подтверждение итоговой оплаты.
   В версии 3 обновлён статус, фактические суммы оставлены пустыми. Версии 1 и 2 сохранены.

В коде проверяются пустые и слишком длинные ТЗ, неподдерживаемые и повреждённые файлы,
посторонние пользователи и групповые чаты, ошибка сервиса, обрезанный ответ модели,
неизвестные или чужие аналоги, пропущенный разработчик, недопустимые цены и диапазоны,
неподтверждённая рекомендация, сохранение после перезапуска и повтор доставки сообщения.
Проверка JSON и ссылок не доказывает смысловую сопоставимость задач: её ещё нужно оценивать на практике.

## Следующие этапы

1. Заполнить токен Telegram, разрешённые ID и ключ OpenRouter. Выбрать модель и лимит расходов.
2. Выполнить первый реальный запрос и проверить техническую работу. Старое известное ТЗ
   можно использовать для такого запуска, но совпадение его цены с историей не доказывает качество прогноза.
3. Разобрать код по пути одного запроса и дать автору небольшое изменение для самостоятельного выполнения.
4. Добавить импорт и ручную правку истории по согласованному формату; заполнить подтверждённые навыки.
   Сейчас данные читаются из подготовленного JSON, импорт CSV и редактирование через бота ещё не реализованы.
5. Когда появятся новые оценки разработчиков, сравнить их с прогнозами и описать реальные расхождения.
6. Подготовить демонстрацию и объяснение собственной логики с учётом комментария преподавателя.

Точной даты сдачи готового кода в задании не указано. Указан срок заявки до 01.10.2026
и защита на сессии. Ориентир «за две недели» относится к размеру проекта.
